# 代码生成 Harness

状态：已实现。实施与验证记录见 [PR #2](https://github.com/XLCYun/nl.js/pull/2)。

配置接口已随 [共享全局配置规格 #3](https://github.com/XLCYun/nl.js/issues/3) 更新；下文描述当前接口。

## 目的与边界

一次模型回复结束，不等于代码生成会话完成。Harness 在 core 中维护多轮 messages：漏调用时提醒，提交格式错误时反馈原因，直到模型通过 `final_output({ asyncFuncBody: string })` 交付一份有效函数体，或会话终止。

Harness 只接管 OpenAI 代码生成会话。Jev 判断、代码缓存、函数体包装和调用处的 eval 沿用现有职责。生成成功只表示提交协议校验通过，不保证函数体语法、行为或真实模型的生成质量。

[原提交协议](final-output-tool.md)最初选择单轮失败即报错。本次将漏调用及可续写的提交错误改为限轮反馈修正；拒绝、过滤、截断及损坏响应仍立即失败。代码生成会话与代码提交的术语见 [GLOSSARY.md](../../GLOSSARY.md)：错误提交可以跨轮修正，每轮只能交付一份最终函数体。

## 轮数配置

轮数通过真正共享的 `globalThis.__NLJS_GLOBAL.maxRounds` 配置，运行时不读取环境变量。按 [README](../../README.md#配置与调试) 完成模型配置后，在自然语言片段执行之前调整：

```js
globalThis.__NLJS_GLOBAL.maxRounds = 10;

async function sum(a, b) {
  return nl`返回 a + b`;
}

sum(1, 2).then(console.log);
```

同一 JavaScript 全局环境的 CJS/ESM 模块共享配置对象；运行时保留调用方已提供的对象。可以修改字段或整体替换对象，后续调用会读取新配置，已经开始的会话继续使用自己的快照。Babel 另为每个含 `nl` 的文件注入 `__NLJS_MODULE`，通过 `generate({ module: __NLJS_MODULE, ... })` 传递独立的源码和变量上下文；模块对象不承担配置。

配置契约：

- 未设置 `maxRounds` 或值为 `undefined` 时默认 10，首轮也计入上限。全局配置对象不存在时会初始化为空对象；显式将整个对象设为 `null` 属于非法配置。
- 配置值是大于零的安全整数；字符串、`null`、零、负数、小数及非有限数无效。
- 每次调用先固定配置快照；OpenAI 缓存未命中时校验轮数，非法值在请求模型前报错。Jev 与缓存命中不使用或校验这个生成配置。
- 模型、key、地址、日志和轮数等设置在本次异步请求前固定，运行中的会话不跟随对象后续修改。OpenAI 命中缓存仍复用生成代码；修改模型不会强制重新生成。
- SDK 自身的 HTTP 重试不作为新的会话轮次。

## 主循环与结束条件

1. `generate()` 沿用现有 provider 分流及代码缓存；只有 OpenAI 缓存未命中时进入 Harness。
2. 读取并校验轮数上限，创建本次会话独立的初始 messages，固定模型和上下文，从第 1 轮开始请求。
3. 收到有效的唯一 `final_output` 时，返回其 `asyncFuncBody`，立即结束生成阶段，无需再向模型请求总结。
4. 遇到可修正问题时，保留本轮 assistant 消息，按下表补充反馈，然后进入下一轮。
5. 如果本轮已达到上限，则直接抛出包含末次失败原因的生成错误，不再发起请求；不可修正的错误立即终止。

请求继续使用 Chat Completions，强制指定 `final_output`，设置 `parallel_tool_calls: false`，不增加 `strict: true`。工具 arguments 仍只能是包含字符串 `asyncFuncBody` 的 JSON 对象，不读取正文或 XML 补救。显式空函数体仍是有效提交。

## 响应与错误处理

| 情况 | 处理 |
| --- | --- |
| 以 `stop` 正常结束、没有工具调用 | 保留 assistant 回复，追加 user 提醒，继续下一轮 |
| 完整工具调用的 arguments 不是合法 JSON，或 JSON 字段不符合约定 | 以 tool 消息反馈具体校验错误，允许下一轮重新提交 |
| 完整的 function 调用使用未知工具名 | 以 tool 消息说明仅有 `final_output` 可用，继续下一轮 |
| 同轮多个完整调用，各自 ID 非空且在当前会话内唯一 | 本轮不采用任何一份提交；按每个调用 ID 逐一反馈 tool 错误，请模型下一轮明确提交一份 |
| 拒绝、内容过滤、截断 | 立即失败 |
| 响应结构损坏，不能构造合法后续历史 | 立即失败 |
| 请求失败 | 沿用 SDK 自身处理，不增加 Harness 网络重试 |
| 已提交代码的 JavaScript 语法或执行错误 | 保留既有执行路径处理，不进入 Harness 修正循环 |

“同轮多个调用”是一次模型响应携带多个工具调用，不是多个轮次里反复修正提交。该轮多份函数体都不作为结果；不擅自选择第一份或最后一份。下一轮可以再次调用工具提交明确结果。

可修正错误只有在剩余轮次内才会继续；耗尽轮数后，错误包含轮数上限及最后一次失败原因。生成阶段失败不写缓存；有效提交仍按原路径包装并缓存，实际执行由调用处的 eval 完成。显式提交空函数体的片段结果为 `undefined`。执行失败不会触发 Harness，也不会撤销既有的代码缓存写入。

## 消息续写的协议约束

函数工具调用包含字符串 `id`、`type: "function"`，以及字符串 `function.name` 和 `function.arguments`。工具反馈为 `role: "tool"`，通过 `tool_call_id` 指向原调用，并以 `content` 反馈错误。

- 漏调用时，保留本轮 assistant 回复，再追加 user 消息，提醒通过 `final_output` 提交函数体。
- 调用参数校验失败时，保留原工具调用，通过对应的 tool 消息返回具体错误。即便 JSON 解析失败，原始 arguments 字符串仍可保留。
- 若一个响应包含多个调用，继续前需要逐一反馈，不能遗漏其中某个调用。
- 项目约定：当前代码生成会话中的工具调用 ID 必须非空且唯一，包括不同轮次之间。ID 记录属于本次会话；独立或并发的其他会话可以复用相同 ID。
- 参数内容不正确与响应结构损坏分别处理：arguments 是对象而不是字符串、工具调用 ID 缺失、为空或全是空白、同轮或跨轮 ID 重复，都立即失败。重复调用不会进入后续请求历史；不伪造或修补 ID 来续写。
- 缺少 choice / message、错误的消息角色、不支持的工具类型，以及结束原因和实际工具调用不一致，归为损坏响应；不伪造工具 ID 或改写损坏字段来续写。

保留收到的 assistant 消息，避免在裁剪字段时丢失已有的服务附加内容；不自行生成推理字段。

## 模块职责

- [core/config.js](../../packages/core/config.js) 初始化共享对象并为每次调用取得配置快照，校验请求配置；[core/index.js](../../packages/core/index.js) 的 `generate()` 处理 provider 分流、上下文构造、缓存检查、函数体包装和成功后的缓存写入。
- [core/harness.js](../../packages/core/harness.js) 的内部 `runCodeGeneration()` 维护本次调用专用的 messages、轮数、工具定义、响应分类、参数校验及错误反馈，成功返回 `asyncFuncBody`。
- 每个自然语言片段的每次生成拥有独立消息历史；并发生成不共用对话，已有的 scope 与源码上下文不在轮次之间重新采集。
- 不新增公共调用方法，不在 Harness 内执行生成代码；Babel / eval 与 Jev 保持现有职责。
- [core/context.js](../../packages/core/context.js) 的生成提示词允许提交错误后再次修正，要求每轮只提交一份最终函数体，有效提交后结束会话。
- 耗尽轮数时抛出带有末次失败原因的生成错误，不再发起下一轮，也不缓存失败内容。

## 验证

运行时通过公开 `generate({ module, scope, source })`、真实 SDK 和模拟 HTTP 响应验证。测试没有请求真实模型，也不证明真实模型兼容性或生成质量。

- 首轮有效提交即结束，保留空函数体、正文不参与提取、函数体原文与现有执行行为。
- 漏调用后提醒，参数错误后按原工具 ID 回填错误，再提交成功。
- 多轮消息顺序与内容保留；未知工具可修正，同轮多个调用逐一反馈，损坏响应直接失败。
- 默认上限为 10；第 10 轮成功与第 10 轮仍失败分别验证，没有第 11 次模型调用。
- `globalThis.__NLJS_GLOBAL.maxRounds` 覆盖默认值，非法配置不发请求；当前会话使用快照，不同调用彼此独立。
- 未配置 `maxRounds` 仍可按默认上限在第 10 轮成功；显式配置 `maxRounds: null` 在请求前失败。
- 生成阶段失败不写缓存；修正成功后缓存仍复用；Jev 与缓存命中不受轮数配置影响。
- 并发生成的消息历史互不混入。保留 core 与 Babel 现有测试，使用模拟模型响应验证，不用真实模型结果代替控制流断言。
- 同轮和跨轮重复的工具 ID 立即失败，后续请求不会携带重复调用；独立或并发会话能复用相同 ID。

另以真实 Babel 编译配置示例，使用模拟 HTTP 验证共享对象的 `maxRounds` 可被 core 读取：上限为 1 时终止，上限为 2 时允许修正并 eval 得到结果。共享配置与独立模块上下文、对象替换、并发会话快照及 SDK 环境回退隔离也由公开入口覆盖。使用方法见 [README](../../README.md)。
