## Spec

- **[P2] 调用 ID 的唯一性只校验同轮，缩窄了已批准的续写约束。** 原规格第 88 行要求：“续写中的调用 ID 必须非空且互不重复”。`packages/core/harness.js:62–67` 在每次 `parseFinalOutput()` 中新建 Set，因此第 1、2 轮可以使用相同 ID 提交无效 JSON，并被一并加入第 3 轮历史（`:136`）。Mock 复现：前两轮均使用 `call_reused` 和 arguments `{`，第 3 轮成功；实际请求 3 次，第 3 次历史的调用 ID 为 `["call_reused", "call_reused"]`。这不符合原先针对续写历史的唯一性约束；当前设计文档改为“同轮 ID 重复”，不能代替批准方案。应在会话内保存已见 ID，跨轮重复也按损坏响应终止，并补充跨轮重复测试。此项依据项目规格，未断言 OpenAI 服务一定拒绝重复 ID。

其余已批准的主循环、反馈分类、10 轮上限、文件级配置快照、上下文/并发隔离、缓存与 Jev 边界均有相应实现；未发现额外功能扩展。审查使用固定基线与原批准规格，仅运行上述 mock 复现，未调用真实模型。
